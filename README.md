# Roostoo Quant Trading Hackathon - momentum breakout bot

An autonomous crypto trading bot for the Roostoo Quant Trading Hackathon.
It trades the Roostoo competition account through the Roostoo API, takes its signals from Binance market data, and runs unattended on AWS EC2 (Sydney).
Every trade is generated by code in this repository; there is no manual trading, override or stop.

## 1. Project overview

**Strategy family:** cross-sectional momentum on breakouts (trend following), long only.

**High-level idea:** crypto trends persist for hours to days after a coin breaks out of its recent range, and the strongest breakouts persist the most.
Every 30 minutes the bot looks for coins closing above their 20-bar high, keeps only the breakouts confirmed by volume and by an active 4-hour breakout, ranks them by 40-bar momentum, and holds the three strongest.
It lets winners run while their channel holds, books a slice of profit at every +3%, and exits a coin when it closes below its 10-bar low.

**Key features**
- Deterministic rule, no discretion and no machine-learned parameters in the trading path.
- Research first: 1,000+ configurations were declared before testing and recorded with their results, failures included (`config/trials.yaml`, `DECISIONS.md`, `FINDINGS.md`).
- Forward-tested on a live paper fleet of 19 books against the same market feed before any book was chosen (`gates/fleet_review.py`).
- Crash-safe execution: every order intent is written and fsynced before it is sent and reconciled against the venue on restart.
- Kill switches for drawdown, API error rate, stale prices and a Roostoo-versus-Binance price mirror check.
- Stays under the 30 calls per minute limit with a rolling call budget.

```
                                  v

                                  |

```

## 3. Strategy explanation

The competition book is `config/competition.yaml`, identical in every rule parameter to the paper book `config/momentum_top3_30m.yaml` it was selected from.

**Universe.** The 30 coins with the highest 30-day median daily dollar volume across all Binance USDT pairs, kept only if Roostoo lists them, excluding stablecoins, tokenized stocks and halted pairs. Refreshed daily.

**Entry conditions** (evaluated at each 30-minute bar close)
1. The close is above the highest close of the previous 20 bars (Donchian breakout).
2. The coin is also in an active 4-hour 20/10 Donchian breakout (higher-timeframe alignment).
3. The breakout bar's volume is at least 1.5 times its 20-bar median.
4. Among qualifying coins, the three with the highest 40-bar momentum are held.

**Exit conditions**
- The close falls below the lowest close of the previous 10 bars.
- Sticky slots: a held leader keeps its slot while its channel holds; new names fill only free slots.

**Position sizing**
- Weights proportional to absolute 40-bar momentum, each capped at 50% of equity, fully deployed across the selected names.
- Profit ladder: every +3% a position gains, 15% of it is sold and the cash is kept.

**Risk management**
- Halt new risk at a 25% drawdown from peak equity, at an API error rate above 25%, or when prices are older than 120 seconds.
- Roostoo prices are checked against Binance each cycle; a persistent deviation over 50 bps halts trading.
- No trading without a readable wallet; no entries on a bar the bot saw late (sleep, outage); a cycle that stalls is aborted and the process respawned.
- Orders are passive limit orders one basis point inside the touch (maker fee 0.05%), cancelled after 5 minutes if unfilled.

**Assumptions**
- Roostoo prices mirror Binance (confirmed by the organisers and checked live).
- Fees measured on the Roostoo test account on 2026-09-30: 0.10% taker, 0.05% maker (`DECISIONS.md#roostoo-keys-2026-09-30`).

## 4. Setup and how to run

Requirements: Python 3.11+.

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env             # then fill in your Roostoo keys
python -m gates.preflight        # read-only checks: clock, venue, keys, market data
python -m pytest tests -q        # 600+ tests
```

Run the live books locally (real orders):

```bash
./run_bots.sh live       # competition + competition_rehearsal
./run_bots.sh status
./run_bots.sh livestop
```

Deploy to EC2 (Session Manager shell, no SSH):

```bash
export REPO_URL=https://github.com/kadoo69/roostoo-hackathon.git
export ROOSTOO_COMP_API_KEY=... ROOSTOO_COMP_SECRET_KEY=... ROOSTOO_TEST_API_KEY=... ROOSTOO_TEST_SECRET_KEY=...
curl -fsSL https://raw.githubusercontent.com/kadoo69/roostoo-hackathon/main/deploy/ec2_bootstrap.sh | sudo -E bash
```

The bootstrap installs Python, clones this repo to `/opt/roostoo-hackathon`, writes `.env` (mode 600), runs the pre-flight and tests, and starts each book as a systemd service that restarts on failure and on reboot.
Updating the strategy means committing here and re-running the same command, so every live change has a commit.

## Trade logs

Every book writes JSON lines under `live/<book>/`: `orders-*.jsonl` (timestamp, pair, side, price, quantity, order ID, status, commission and the full API response fields), `signals-*.jsonl` (the target and why), `cycles-*.jsonl` (equity, positions, risk state), `reconcile-*.jsonl` and `errors-*.jsonl`.
`./run_bots.sh trades` exports a FIFO trade blotter as CSV.
