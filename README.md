# Roostoo Quant Trading Hackathon - volatility-scaled momentum ride

An autonomous crypto trading bot for the Roostoo Quant Trading Hackathon.
It trades the Roostoo competition account through the Roostoo API, takes its signals from Binance market data, and runs unattended on AWS EC2 (Sydney).
Every trade is generated by code in this repository; there is no manual trading, override or discretionary order.

## 1. Project overview

**Strategy family:** short-horizon momentum (burst continuation), long only, directional.

**High-level idea:** in this coin pool most small moves revert within minutes, but a move that is large relative to the coin's own recent volatility tends to keep going for hours.
Every 5 minutes the bot measures each coin's 15-minute return against that coin's normal 15-minute volatility over the last 24 hours, buys the coins that move at least 2.5 standard deviations, and holds up to three.
Each position takes profit at a target sized to the coin's own daily volatility, books a slice of profit at every +3%, and is closed after 24 hours at the latest.

**Key features**
- Deterministic rule, no discretion and no machine-learned parameters in the trading path.
- Per-coin scaling: the entry trigger and the profit target adapt to each coin's own volatility, so BTC and PUMP are judged on their own scale.
- Research first: every configuration was declared before testing and recorded with its result, failures included (`config/trials.yaml`, `DECISIONS.md`, `FINDINGS.md`).
- Forward-tested on a live paper fleet against the same market feed before the competition book was chosen.
- Crash-safe execution: every order intent is written and fsynced before it is sent and reconciled against the venue on restart.
- Kill switches for drawdown, API error rate, stale prices and a Roostoo-versus-Binance price mirror check.
- Stays under the 30 calls per minute limit with a rolling call budget.

## 3. Strategy explanation

The competition book is `config/competition_z25.yaml`, run by `bot/scalper_adaptive_run.py` with the ride rule in `signals/burst_rider.py`.
It changed during the competition as the rules allow (FAQ Q28); every change is a commit with its evidence in `DECISIONS.md` (see "Strategy changes during the competition" below).

**Universe.** 27 liquid coins: the top by 30-day median dollar volume across Binance USDT pairs that Roostoo lists, excluding stablecoins and tokenized stocks, refreshed daily.

**Entry conditions** (evaluated at each 5-minute bar close)
1. For every coin, z = its 3-bar (15-minute) return divided by the standard deviation of its 3-bar returns over the previous 288 bars (24 hours).
2. A coin with z >= 2.5 is bought if a slot is free (at most 3 positions) and it was not entered in the last 12 bars (1 hour).
3. When more coins trigger than slots are free, the largest moves are taken first.

**Exit conditions**
- Take profit when a bar's high reaches the target: 2 x the coin's own one-day volatility at entry (its 3-bar std x sqrt(96)), fixed at entry (about 1% for BTC up to about 16% for PUMP).
- Otherwise exit after 288 bars (24 hours).

**Position sizing**
- One third of equity per position, at most three positions, no leverage.
- Profit ladder: every +3% a position gains, 15% of it is sold and the cash is kept.

**Risk management**
- Halt new risk at a 25% drawdown from peak equity, at an API error rate above 25%, or when prices are older than 120 seconds.
- Roostoo prices are checked against Binance each cycle; a persistent deviation over 50 bps freezes trading.
- No trading without a readable wallet; no entry on a signal the bot saw late or on the first bar after a cold start; a cycle that stalls is aborted and the process respawned.
- Orders are passive limit orders at the touch (maker fee 0.05%); an unfilled entry is cancelled after 5 minutes and never chased, an unfilled exit is re-sent at market.

**Directional, 1x, no leverage**
- Directional only: no market making and no arbitrage.
- Gross exposure is capped at 1.0 of equity (no leverage), each coin at 0.5.
- The ride is long-only: every short sleeve we tested lost money out of sample (`DECISIONS.md#crash-shorts-outcome`).

**Assumptions**
- The bot adopts whatever the Roostoo wallet holds at start (the organisers give each team 100k) and sizes every position as a fraction of equity, so the starting amount changes no decision.
- Only the bot calls Roostoo with the competition key; the read-only pre-flight checks that key for presence without calling the API (`DECISIONS.md#comp-key-bot-only-2026-10-02`).
- Roostoo prices mirror Binance (confirmed by the organisers and checked live).
- Fees measured on the Roostoo test account on 2026-09-30: 0.10% taker, 0.05% maker (`DECISIONS.md#roostoo-keys-2026-09-30`).

## 4. Setup and how to run

Requirements: Python 3.11+.

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env             # then fill in your Roostoo keys
python -m gates.preflight        # read-only checks: clock, venue, keys, market data
python -m pytest tests -q        # 600+ tests
```

Run the live books locally (real orders):

```bash
./run_bots.sh live       # the live books
./run_bots.sh status
./run_bots.sh livestop
```

Deploy to EC2 (Session Manager shell, no SSH):

```bash
export REPO_URL=https://github.com/kadoo69/roostoo-hackathon.git
export ROOSTOO_COMP_API_KEY=... ROOSTOO_COMP_SECRET_KEY=... ROOSTOO_TEST_API_KEY=... ROOSTOO_TEST_SECRET_KEY=...
curl -fsSL https://raw.githubusercontent.com/kadoo69/roostoo-hackathon/main/deploy/ec2_bootstrap.sh | sudo -E bash
```

The bootstrap installs Python, clones this repo to `/opt/roostoo-hackathon`, writes `.env` (mode 600), runs the pre-flight and tests, and starts each book as a systemd service that restarts on failure and on reboot.
Updating the strategy means committing here and re-running the same command, so every live change has a commit.

## Trade logs

Every book writes JSON lines under `live/<book>/`: `orders-*.jsonl` (timestamp, pair, side, price, quantity, order ID, status, commission and the API response fields), `signals-*.jsonl` (the target and why), `cycles-*.jsonl` (equity, positions, risk state), `reconcile-*.jsonl` and `errors-*.jsonl`.
`./run_bots.sh trades` exports a FIFO trade blotter (`trades_closed.csv`, `trades_open.csv`) for the live books.

The committed copy for evaluation is `logs/`: `logs/ec2/<book>/` holds the logs and trade CSVs from the EC2 instance (live since 2026-10-02 12:36Z), one folder per unit that traded the competition account and `logs/mac/<book>/` the same books before the move.
`python3 deploy/export_logs.py` refreshes it from the instance; the 30-second equity snapshots stay on the host.
